# Moodify standalone migration execution checklist

This file is the durable execution checkpoint for the standalone Android migration. The interactive plan in docs/moodify-standalone-plan.html remains the architecture source of truth; this file records evidence from the current repository.

Status vocabulary: PASS means executed and verified, PARTIAL means the implemented slice passed but the full matrix is incomplete, FAIL means executed and failed, BLOCKED means an external dependency prevents execution, and NOT TESTED means no evidence yet. Checkboxes marked `[~]` are PARTIAL.

## Current progress — 2026-11-02

The Android standalone migration has the core architecture in place; release acceptance remains open, excluding download/offline features as requested. **Plan completion is approximately 67% by engineering scope, not 67% release-ready:** the remaining third is concentrated in live reliability and physical-device proof rather than missing foundations. Native InnerTube catalog/search, local persistence, direct device-side stream resolution, on-device WebPO token generation, Media3 playback, and web-preservation gates are implemented. Fresh source verification on 2026-11-02 passed **41/41 Android unit tests** plus debug assembly, and the React/Node app passed **132 tests**, typecheck, and production build. A fresh unsigned release assembly and `lintDebug` run also passed with **0 errors and 64 warnings**. The focused API 37 live catalog class previously passed **3/3**, covering Home/Explore/Moods, typed artist/album details, and playlist continuation. A separate broader live run had **one MWEB Media3 HTTP 403**; a prior isolated retry passed 2/2, so full playback acceptance still needs a clean wider rerun. Emulator acceptance proves catalog and playback with the Moodify host blocked, queue handoff, MediaStyle notification controls, region switching, chart navigation, the native Moods & genres flow, and live playlist continuation. The lyrics screen has timed line/word highlighting, ArchiveTune-inspired active-line fade/blur, provider romanization parsing, API-29+ on-device ICU transliteration fallback, and a persistent toggle. A privacy-safe diagnostics card and redacted in-memory event list are available in About; playback logs omit track IDs, raw exceptions, signed URLs, and token fragments. Playback retries the same profile once for HTTP 410 or a known near-expiry URL before rotating. Remaining work includes a real CDN 410/expiry recovery trace, broader provider coverage and advanced lyrics tools, physical-device acceptance, complete catalog/locale coverage, v4→v5 state-migration runtime evidence, and production signing.
